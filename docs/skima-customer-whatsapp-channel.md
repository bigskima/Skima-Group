# SKIMA LPG customer WhatsApp channel

## Architecture
SKIMA uses Meta's official WhatsApp Business Cloud API directly. The webhook is a Supabase Edge Function. The channel is customer-only and reuses the existing SKIMA profile, cylinder, saved-location, station eligibility, pricing, order, wallet, escrow, dispatch, and driver-location systems. It must never create its own wallet, price LPG locally, accept a payment screenshot as proof, or update an order to "paid" without verified backend state.

## Customer flow implemented in code
1. A signed-in customer opens SKIMA app → Account → WhatsApp linking and generates a one-time 16-character code.
2. The customer sends that code to the official WhatsApp number. The code is stored only as a SHA-256 hash, expires after 10 minutes, is single-use, and has a per-number attempt limit.
3. Linked customers can select one of their saved cylinders, enter refill kilograms, select saved pickup and delivery locations, choose an eligible approved station option, and receive a quote generated by SKIMA pricing.
4. The customer must reply CONFIRM before an LPG order is created. SKIMA's current customer-terms check still applies.
5. Payment is attempted through the same wallet reservation + escrow + dispatch transaction used by the app. The bot reports success only after it re-reads the order and verifies the payment status. If wallet funds or eligible dispatch are unavailable, it says payment remains pending and directs the customer to SKIMA app Wallet → Top up.
6. Customers can list their recent orders and see the latest recorded driver location for active orders, when that location is available.

## App handoff configuration

- `EXPO_PUBLIC_SKIMA_WHATSAPP_NUMBER`: the official WhatsApp business number in international digits-only format, without a plus sign (for example, a configured Nigerian number begins with `234`). This value is public and lets Account → WhatsApp ordering open the correct `wa.me` chat with the generated one-time linking code prefilled. Configure it in the mobile app's build environment (Expo/EAS and any deployed web build that serves this app). Do not ship a guessed or temporary test number in production.

## Required Supabase Edge Function secrets
- `SKIMA_WHATSAPP_VERIFY_TOKEN`: random webhook verification token.
- `SKIMA_WHATSAPP_APP_SECRET`: Meta app secret used for `X-Hub-Signature-256`.
- `SKIMA_WHATSAPP_ACCESS_TOKEN`: server-side Meta Cloud API access token.
- `SKIMA_WHATSAPP_PHONE_NUMBER_ID`: Meta phone number ID, not the public phone number.
- `SKIMA_WHATSAPP_GRAPH_API_VERSION`: supported Graph API version configured for the Meta app.
- Supabase provides `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` to Edge Functions; never copy the service-role key into the app or GitHub.

## Meta launch checklist
1. Create or select the SKIMA Meta Business Portfolio and Meta developer app; add WhatsApp and register/verify the business phone number.
2. Use the Meta test number and test recipient first. Configure the webhook callback URL for the deployed `skima-whatsapp-webhook` Edge Function and the same verify token; subscribe to the `messages` webhook field.
3. Store the five WhatsApp secrets in Supabase Edge Function secrets. Configure the version actually supported by the Meta app, not a guessed placeholder.
4. Run signed webhook tests, secure account-link tests, quote/confirmation/payment/dispatch tests and retry/idempotency checks before enabling the production phone number.
5. Keep customer replies within the user-initiated service window. For business-initiated messages outside that window, use Meta-approved templates and a recorded valid opt-in. This initial scope only responds to inbound customer messages; it does not start unsolicited marketing or automatic proactive driver notifications.

## Provider and costs
The direct Meta Cloud API is the recommended provider; a separate paid bot builder is not required. Meta provides a test environment. Production messaging charges depend on current Meta pricing, message category and destination. See https://whatsappbusiness.com/developers/developer-hub/ and https://whatsappbusiness.com/products/platform-pricing/.

## Security and release
Webhook GET challenge verification and POST HMAC signature validation are required. Inbound Meta message IDs are de-duplicated, and raw inbound text / one-time linking codes are not written into the event payload. Privileged WhatsApp RPCs must be executable by `service_role` only and must validate linked ownership before calling canonical LPG functions. Do not deploy live sending until Meta credentials, number approval, webhook subscription, account linking, migration application and backend tests have been verified.
